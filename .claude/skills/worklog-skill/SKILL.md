## 通用前置操作（每次读写前必做）

用 Bash 工具执行以下命令获取当前日期和周信息：

```bash
python3 -c "
import datetime
today = datetime.date.today()
weekday = today.weekday()  # 0=周一
monday = today - datetime.timedelta(days=weekday)
sunday = monday + datetime.timedelta(days=6)
print('TODAY', today.strftime('%Y-%m-%d'))
print('WEEK_DIR', monday.strftime('%Y-week%m%d-') + sunday.strftime('%m%d'))
print('DRAFT', today.strftime('.draft-%Y-%m-%d.md'))
print('DAILY', today.strftime('%Y-%m-%d-daily.md'))
print('WEEKLY', monday.strftime('%Y-week%m%d-') + sunday.strftime('%m%d'))
"
```

根据输出结果：
- 基础目录：`C:\Users\12800\Desktop\日报-周报`
- 本周文件夹：`{基础目录}/{WEEK_DIR}/`
- 草稿文件：`{本周文件夹}/{DRAFT}`
- 日报文件：`{本周文件夹}/{DAILY}`
- 周报文件：`{本周文件夹}/{WEEKLY}`

**每次操作前必须创建本周文件夹**（如果不存在）：
```bash
mkdir -p "{本周文件夹}"
```

## 操作 1：追加草稿（最常用）

触发场景：
- CLAUDE.md 指令自动触发（`[auto]`）
- Skill args 包含记录内容
- 用户说"记录：xxx""记一下，xxx"

### 执行步骤

1. **执行【通用前置操作】**获取路径
2. **翻译描述**：将传入的记录内容翻译为自然语言，**删除所有代码细节**（变量名、文件路径、函数名、技术术语如 payload/hook/schema 等）
3. **获取时间戳**：
   ```bash
   date +%H:%M
   ```
4. **追加写入草稿文件**：
   ```
   - [auto] HH:MM {翻译后的自然语言描述}
   ```
   如果文件不存在，Write 工具会自动创建。
5. **验证**：用 Read 工具读取草稿文件最后 3 行，确认写入成功
6. **向用户汇报**：仅简要告知"已记录到日报草稿：{一句摘要}"，**不要展示文件全文**

### 描述翻译示例

原始描述：
- ❌ "修改 main.py 的 RTSPReader，添加 gpu_decoder.GPUVideoReader 支持" → ✅ "为视频读取模块增加了 GPU 硬件解码能力"
- ❌ "backend/camera_manager.py 集成 GPUVideoReader" → ✅ "多摄像头管理也接入了 GPU 解码"
- ❌ "requirements.txt 添加 av" → ✅ "补充了硬件解码所需的依赖库"

## 操作 2：生成日报

触发场景：用户说"生成日报""写日报""今天做了什么"

### 执行步骤

1. **执行【通用前置操作】**获取路径
2. **读取草稿文件**：用 Read 工具读取 `.draft-YYYY-MM-DD.md`
3. **如果草稿为空**：回复"今天还没有记录任何工作事项，无法生成日报。"
4. **如果草稿有内容**：
   - 去重：相同事项只保留一条
   - 过滤：跳过 `[invalid]` 标记的条目
   - 分类：按关键词归入 `[功能]`/`[Bug修复]`/`[优化]`/`[文档]`/`[其他]`
   - 提取"进行中""明日计划"到对应段落
5. **写入日报文件** `YYYY-MM-DD-daily.md`
6. **删除草稿文件**（或重命名为 `.draft-YYYY-MM-DD.md.bak` 如果用户要求保留）
7. **向用户汇报**：仅报告文件路径，**禁止在对话中打印日报全文**

## 操作 3：生成周报

触发场景：用户说"生成周报""这周总结""周报"

### 执行步骤

1. **执行【通用前置操作】**获取路径
2. **扫描本周所有日报**：用 Bash 工具列出本周文件夹内所有 `*-daily.md` 文件
3. **读取所有日报**并汇总
4. **去重分类**并按模板生成周报
5. **写入周报文件** `YYYY-weekMMMDD-MMDD.md`
6. **向用户汇报**：仅报告文件路径

## 格式规范

### 草稿格式（追加）
```markdown
- [auto] 14:32 修复了登录会话偶发过期的认证问题
- [manual] 15:10 记录了：下午要开会讨论方案
```

### 日报模板
```markdown
# 工作日报 — YYYY-MM-DD

## 今日完成

### [功能]
- xxx

### [Bug修复]
- xxx

### [优化]
- xxx

### [文档]
- xxx

### [其他]
- xxx

## 进行中
- xxx

## 明日计划
- xxx

## 备注
- 自动记录 X 条，手动记录 Y 条
```

### 周报模板
```markdown
# 工作周报 — YYYY-MM-DD 至 YYYY-MM-DD

## 本周概览
- 完成功能：X 项
- 修复 Bug：Y 个
- 性能优化：Z 项
- 文档/其他：W 项

## 详细内容

### 功能
- MM-DD：xxx

### Bug修复
- MM-DD：xxx

### 优化
- MM-DD：xxx

## 下周计划
- xxx
- yyy [未完成]
```

## 规则约束

- **时间戳**：使用 `date +%H:%M` 获取的本地时间
- **语言**：草稿条目必须使用自然语言，禁止代码细节
- **分类关键词**：
  - `[功能]`：实现了、新增了、添加了
  - `[Bug修复]`：修复了、解决了
  - `[优化]`：优化了、重构了、提升了、降低了
  - `[文档]`：更新了、完善了、编写了
- **状态过滤**：优先记录完成态，忽略将来态
- **用户否认**：若用户说"这不是工作""忽略刚才那条"，将最近一条记录标记为 `[invalid]`
- **汇报格式**：记录完成后必须向用户简要告知 **"已记录到日报草稿：{一句摘要}"**，禁止在对话中展示文件全文

## Edge Cases

- **草稿不存在**：首次使用时自动创建空草稿
- **同一天多次生成日报**：覆盖已有日报文件
- **跨午夜**：以系统时间为准，23:59 和 00:01 分属两天
- **非工作会话**：非工作相关内容不记录
